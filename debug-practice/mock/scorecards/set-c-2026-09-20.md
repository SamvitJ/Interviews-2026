## What to work on

**The interpreter was available and went unused.** On m3 the right change
("normalize before the `seen` check") came out within a couple of minutes — the
cause was correctly identified early. What was missing was Python's
hash-at-insertion behavior, which was a genuine knowledge gap and was signaled
honestly ("not sure," then a correct guess that the hash is computed once).
That is not a reasoning failure and is not scored as one.

What *is* scored: the gap was empirically reachable and nobody reached for it.
`print(len(seen))` next to `record in seen` shows a set that contains an object
while reporting that it doesn't — hash-at-insertion falls out of that in thirty
seconds with no prior knowledge of the term. Same note as set A m2 (`re.findall`
would have settled the "two matches" question instantly) and set B m3 (the
instance-vs-class attribute check had to be handed over). Three sessions, one
habit.

Drill: when you don't know the mechanism, don't reason harder — write the
two-line experiment that would distinguish your hypotheses, *then* state the
causal chain in one sentence. "X is stored under hash H1; mutation changes it to
H2; lookup at H2 misses the bucket at H1."

**Axis 2 held flat** (3 → 2 → 2 → 2) rather than collapsing on bug 4, so the
predicted reversion under pressure did not happen.

**One evidence miss on m2.** Initial read was "a secondary lexicographic sort
isn't being applied" — but the output was `['zebra', 'mango', 'apple']`, exact
reverse alphabetical. The evidence said "applied and reversed," not "absent."
Updated cleanly when pushed, but the first pass looked at the output and didn't
actually read it.

## Facts that were missing

All three are read-once-own-forever:

- **Python's sort is stable.** Equal keys keep input order. This is the whole
  reason `sorted(sorted(x, key=secondary), key=primary, reverse=True)` works.
- **Sets hash at insertion.** Mutating a stored object's hash-relevant state
  makes it permanently unreachable. Corollary: don't put mutable objects in sets.
- **`return` inside `finally` discards a propagating exception.** Same for
  `break` and `continue`.

Also worth keeping: `math.floor(a / b)` does float division first and loses
precision on large ints; `a // b` stays exact.
